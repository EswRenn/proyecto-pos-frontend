1. Contexto & Modelo de Negocio

De la Fragmentación a la Centralización Operativa

Optimización del ciclo de vida de afiliación y configuración de terminales punto de venta.

⚠️

El Problema: Procesos Dispersos

  • Múltiples Plataformas Aisladas: El personal operaba entre 4 sitios web diferentes (VHQ, AS400, Mipos, CSP).
  • Errores de Transcripción Manual: Pérdida de integridad en identificadores de comercio, NIT y números de serie.
  • Tiempos de Despliegue Excesivos: Días de retraso entre la captura inicial del cliente y la entrega técnica.
  • Carencia de Bitácora Centralizada: Sin trazabilidad unificada de rechazos o devoluciones documentales.
🚀

La Solución: Plataforma POS Central

  • Flujo Único B2B en 5 Etapas: Unifica la captura de requisitos en un pipeline secuencial guiado por rol.
  • Arquitectura Desacoplada: Frontend interactivo React (SPA) con orquestación de microservicios Spring Boot.
  • Automatización de Afiliados: Generación numérica de 8 dígitos de alta entropía por tipo de venta.
  • Trazabilidad y Notificaciones en Vivo: Auditoría completa de cada cambio y motivo de devolución.

2. Arquitectura de Software

Ecosistema Distribuido y Orquestación Híbrida

Integración ágil entre frontend moderno, microservicios REST y protocolos legados SOAP.

⚛️

Frontend React

Single Page Application (SPA) en React 19 + Vite 8.3. Virtual DOM optimizado, navegación reactiva por roles y componentes modulares con Tailwind CSS.

☕

Backend Java 21

Microservicios en Spring Boot 3.2. Controladores REST desacoplados por dominio, mapeo JPA/Hibernate con transacciones @Transactional.

🛡️

API Gateway

Kong Enterprise / Spring Cloud Gateway. Enrutamiento dinámico, políticas CORS, balanceo de carga y mitigación de ataques perimetrales.

🏛️

Core Legacy SOAP

Adaptadores SOAP para enlace con mainframes bancarios AS400 (códigos OCG, OCA, T 002) y consolas de hardware VHQ.

Base de Datos Relacional: PostgreSQL 16 con garantías ACID para prevenir condiciones de carrera en afiliados y TIDs. Persistencia Segura

4. Aseguramiento de Calidad

Metodologías de Prueba del Producto

Estrategia en dos niveles conforme a la Matriz de Ciclo de Vida de Software.

1. Pruebas de Unidad (Unit Testing)

10/10 Aprobados (100%)

Objetivo: Identificar defectos en algoritmos y componentes aislados utilizando mocks para dependencias externas (TDD).

  • Algoritmo de 8 Dígitos: Validación estricta con regex /^\d{8}$/ en 1,000 iteraciones (rango 10000000..99999999 sin ceros iniciales).
  • Días Hábiles: Validación matemática de fechas (lunes-viernes true, fines de semana false).
  • Mapeo de Hardware: Asignación correcta de subsistemas y códigos AS400 (OCG, OCA, T 002).
  • Formatos Tributarios: Validación de longitud exacta de 13 dígitos para DPI y formato con guión para NIT.

2. Pruebas de Integración (Integration)

6/6 Aprobados (100%)

Objetivo: Asegurar la compatibilidad de interfaz, deserialización de datos y comunicación entre módulos.

  • Deserialización JSON: El payload de React con datos fiscales es mapeado íntegramente por Jackson en Spring Boot.
  • Adaptador SOAP AS400 / VHQ: Construcción y parseo exitoso del sobre XML con <soapenv:Envelope>.
  • Cascada Transaccional Relacional: Creación e integridad de claves foráneas: Solicitud → Afiliado → Terminal → OrdenDespacho.
  • Sincronización de Estados HTTP: Transiciones fluidas a estados Aprobada y Confirmación de Instalación.

6. Normativas Internacionales

Cumplimiento de los 3 Estándares de Calidad

Alineación rigurosa con normativas de calidad de software, seguridad web y transaccionalidad.

ISO/IEC 25010

Calidad y Rendimiento

  • Rendimiento DOM: Bundle JS comprimido de solo 106.24 KB (gzip).
  • Tiempo de Build: Compilación en Vite de 677 ms (< 2s).
  • Latencia REST: 1.57 ms en peticiones locales (< 125 ms meta).
  • Mantenibilidad: 0 errores fatales en análisis estático de código.

OWASP ASVS v4.0

Seguridad de Aplicación Web

  • Mitigación SQLi: Consultas preparadas en JPA/Hibernate neutralizan inyecciones en datos fiscales.
  • Mitigación XSS: Escape nativo en JSX previene ejecución de scripts en cliente.
  • Déficit Detectado: Falta de tokens JWT y uso de wildcard * en CORS de Spring Boot.

PCI-DSS v4.0

Seguridad de Pagos

  • Rangos de Bines: Validación de 9 dígitos en CSP con regla binFrom ≤ binTo.
  • No Almacenamiento PAN: Cero datos de tarjetas o CVV en la base de datos central.
  • Cifrado en Tránsito: Arquitectura diseñada con terminación TLS 1.3 en Gateway.

7. Hallazgos & Plan de Acción

Detalles por Mejorar y Roadmap Técnico

Puntos de optimización identificados para elevar el cumplimiento del 90.3% al 100%.

Seguridad & Autenticación (P0)

  • Cifrado de Credenciales: Integrar BCryptPasswordEncoder y añadir @JsonProperty(access = WRITE_ONLY) para no exponer claves en GET /api/usuarios.
  • Sesiones sin Estado (JWT): Habilitar spring-boot-starter-security para proteger endpoints y validar roles en backend.
  • Restricción CORS: Reemplazar el comodín * por el origen exacto del frontend.

Integración & Persistencia (P1)

  • Cardinalidad de Afiliados (1:N): Actualizar Afiliado.java a @ManyToOne para persistir simultáneamente afiliados de venta normal, cuotas y puntos.
  • Campos Logísticos en Backend: Añadir columnas tecnico_asignado y direccion_entrega a la tabla ordenes_despacho.
  • Exportador CSV: Corregir el salto de línea literal \n en DashboardView.jsx y anteponer BOM UTF-8 para Excel.
